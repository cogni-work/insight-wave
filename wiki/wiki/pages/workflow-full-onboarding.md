A meta-pipeline: it sequences the other workflows rather than chaining plugins itself. Like [[workflow-docs-pipeline]] it carries no canonical workflow ID and no `docs/workflows/` companion — see [[concept-canonical-workflow-ids]].

## Pipeline

```
workspace init → orientation docs → the seven canonical templates → practice on real work
```

## Duration

4–5 hours total, best spread across sessions.

## End deliverable

A configured workspace, a working mental map of the ecosystem, and at least one real artifact produced end to end.

## Steps

**1 — Initialize the workspace.** `cogni-workspace:manage-workspace`, against your project directory. Produces the configured workspace: env vars, settings, themes and plugin discovery. Do this before anything else — every plugin reads from it. Choose the language preference during setup, and pick a theme with `cogni-workspace:manage-themes` Operation 11 (Select Theme), which affects all visual output downstream ([[concept-theme-inheritance]]).

**2 — Read the orientation docs.** `docs/getting-started.md` covers installation and first run; `docs/ecosystem-overview.md` answers what exists and how it connects. Both are generated by cogni-docs and track the current plugin set, so they do not go stale the way a hand-maintained map would. [[ecosystem-plugin-selection]] is the wiki-side equivalent.

**3 — Walk the canonical templates.** Each names the plugin chain, the invocation per step, and the pitfalls:

| Workflow | Pipeline | Time |
|---|---|---|
| [[workflow-install-to-infographic]] | workspace → themes → visual | ~45 min |
| [[workflow-research-to-report]] | knowledge → narrative → visual | ~45 min |
| [[workflow-trends-to-solutions]] | trends → portfolio → marketing | ~50 min |
| [[workflow-content-pipeline]] | marketing → narrative → copywriting → visual | ~50 min |
| [[workflow-portfolio-to-pitch]] | portfolio → narrative → sales → visual | ~50 min |
| [[workflow-portfolio-to-website]] | portfolio → workspace → website | ~45 min |
| [[workflow-consulting-engagement]] | cogni-consult, knowledge-backed | ~60 min |

Start with install-to-infographic: it is the shortest chain that still crosses three plugins, and the artifact doubles as a smoke test that the workspace is configured correctly. Each canonical ID has a matching tutorial at `docs/workflows/<id>.md` — read it alongside the template. Check plugin prerequisites before starting a pipeline. `consulting-engagement` is the capstone.

**4 — Practice.** Reinforce with real work rather than more reading. Pick a small project in your own domain; read [[ecosystem-plugin-selection]] to find the right plugins and see how they chain, and [[ecosystem-command-reference]] for a command refresher, and `cogni-workspace:cogni-issues` to file problems you hit.

## Common pitfalls

- **Skipping install-to-infographic.** Even experienced users benefit from walking the workspace → themes → visual handoff once, because it exercises the configuration every other pipeline depends on.
- **Reading without running.** The templates are playbooks, not tutorials. The handoff shapes only stick once you have produced an artifact.
- **Binge onboarding.** Spread the pipelines across sessions; the concepts settle better with gaps between them.
